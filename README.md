# green-api-max-demo

Веб-интерфейс для отправки и получения текстовых сообщений в мессенджере [MAX](https://max.ru/) через [GREEN-API](https://green-api.com/max). Внешний вид — по образцу [web.max.ru](https://web.max.ru/).

Тестовое задание на должность «Фронтенд разработчик React».

## Возможности

Сценарий из задания:

1. Вход по учётным данным инстанса GREEN-API: `idInstance` и `apiTokenInstance`.
2. Новый чат по номеру телефона получателя.
3. Отправка текстового сообщения.
4. Получение ответа: он появляется в чате без перезагрузки страницы.

Дополнительно:

- список чатов со счётчиком непрочитанных; число непрочитанных — в заголовке вкладки;
- статус отправки: «Отправляется», «Отправлено», «Не отправлено» с повтором;
- при открытии чата подгружается его прежняя переписка с сервера;
- чаты и сообщения сохраняются между перезагрузками;
- индикатор соединения и предупреждение, если в настройках инстанса выключены нужные уведомления;
- русский и английский язык;
- светлая, тёмная и системная тема;
- адаптивная вёрстка от 320px: на узком экране — либо список чатов, либо переписка;
- работа с клавиатуры и скринридером (Lighthouse Accessibility — 100).

## Подготовка GREEN-API

Приложению нужен инстанс GREEN-API для MAX с авторизованным аккаунтом MAX.

1. Зарегистрируйтесь в [личном кабинете GREEN-API](https://console.green-api.com/).
2. Создайте инстанс для MAX. Для проверки хватит бесплатного тарифа «Разработчик» (Developer).
3. Авторизуйте в инстансе свой аккаунт MAX по инструкции в личном кабинете (QR-код). Статус инстанса должен стать «Авторизован» (`authorized`).
4. На странице инстанса возьмите `idInstance` и `apiTokenInstance` — их вводят на экране входа. Если в кабинете указан свой `apiUrl`, укажите его в поле «apiUrl»; по умолчанию — `https://api.green-api.com`.
5. **Включите уведомления** в настройках инстанса. По умолчанию они выключены, и без них приложение не получит ни одного сообщения:

   | Настройка в личном кабинете                                | Параметр API                | Нужна                  |
   | ---------------------------------------------------------- | --------------------------- | ---------------------- |
   | Получать уведомления о входящих сообщениях и файлах        | `incomingWebhook`           | **обязательно**        |
   | Получать уведомления о сообщениях, отправленных с API      | `outgoingAPIMessageWebhook` | рекомендуется          |
   | Получать уведомления о сообщениях, отправленных с телефона | `outgoingMessageWebhook`    | рекомендуется          |
   | Получать уведомления о статусах отправленных сообщений     | `outgoingWebhook`           | рекомендуется          |
   | Получать уведомления об изменении состояния авторизации    | `stateWebhook`              | рекомендуется          |
   | Адрес отправки уведомлений (URL)                           | `webhookUrl`                | **должен быть пустым** |

   Настройки применяются в течение 5 минут. Если какая-то из них выключена, приложение покажет предупреждение под шапкой списка чатов.

6. Для проверки нужен второй аккаунт MAX — собеседник, который ответит на сообщение.

> **Лимиты тарифа «Разработчик»:** 3 чата в месяц (отправка и получение) и 100 проверок номера (`checkAccount`) в месяц; сбрасываются 1-го числа. Для проверки достаточно одного собеседника.

## Локальный запуск

Нужен [Node.js](https://nodejs.org/) 22.12 или новее (в `.nvmrc` — 24) и npm.

```sh
git clone https://github.com/vptorkhov/green-api-max-demo.git
cd green-api-max-demo
npm ci
npm run dev
```

Откройте http://localhost:5173/ и войдите с `idInstance` и `apiTokenInstance` вашего инстанса.

Production-сборка и её локальный просмотр:

```sh
npm run build
npm run preview
```

Сборка — в папке `dist/` (статические файлы, подходит любой статический хостинг); просмотр — http://localhost:4173/.

Переменные окружения и бэкенд не нужны: приложение обращается к GREEN-API напрямую из браузера (CORS разрешён).

## Структура проекта

Общие слои в корне `src/` и домены в `features/`. Импорты идут только «вниз»: `app` → `features` → общие слои. Снаружи домен доступен только через свой `index.ts`.

```
src/
  app/              корень: провайдеры, граница ошибок, переключение экранов
  features/
    auth/           вход, учётные данные, статус инстанса
    chat/           список чатов, создание чата, переписка, отправка, получение
  components/       общие компоненты: ui/ (кнопки, поля, иконки), выбор языка и темы
  services/         HTTP-клиент GREEN-API и типизированная ошибка
  hooks/            общие хуки: localStorage, тема, язык
  constants/  types/  utils/
  localization/     i18next и словари ru / en
  styles/           глобальные стили и дизайн-токены
```

Домен устроен одинаково: `components/` (каждый компонент в своей папке с CSS-модулем), `hooks/`, `services/`, `types/`, `utils/`, `constants/`.

## Как это работает

**Запросы.** Все обращения к GREEN-API идут через один клиент (`services/greenApiClient.ts`). Ответ сервера проверяется type guard'ом, ошибки приводятся к типизированному `GreenApiError` с видом (`network`, `unauthorized`, `rateLimit`, `quotaExceeded`…) — по нему выбирается текст для пользователя. Если учётные данные перестали действовать (401), приложение выходит на экран входа и показывает причину.

**Вход.** Учётные данные проверяются запросом `getStateInstance`: войти можно только с авторизованным инстансом, для остальных статусов показывается понятная причина.

**Новый чат.** Номер нормализуется и проверяется локально. Если чат с этим номером уже есть, он открывается без запроса — `checkAccount` ограничен 100 вызовами в месяц. Иначе `checkAccount` проверяет, что у номера есть аккаунт MAX, и возвращает его `chatId`.

**Отправка — оптимистичная.** Сообщение сразу появляется в переписке со статусом «Отправляется» и временным id. Ответ `sendMessage` заменяет id на `idMessage` сервера, ошибка — статус «Не отправлено» и кнопка «Повторить».

**Получение — HTTP API, long polling.** Один цикл на экран чата: `receiveNotification` (сервер держит запрос до 20 секунд) → событие применяется к хранилищу → `deleteNotification`. Уведомление удаляется только после применения, поэтому при сбое оно придёт повторно, а дубли отсекаются по `idMessage` в пределах чата. Так же отсекается уведомление о собственном отправленном сообщении. Время сервера считается источником правды: своё сообщение после уведомления встаёт на место по времени сервера. При ошибке сети цикл повторяет запрос с паузой от 1 до 30 секунд и показывает индикатор «Нет соединения».

**История.** При открытии чата его последние 100 сообщений подгружаются `getChatHistory` и сливаются с локальными без дублей.

**Хранение.** Чаты и сообщения — в `localStorage`, отдельно для каждого инстанса; хранятся последние 200 сообщений чата. Сообщение, которое при перезагрузке осталось «Отправляется», становится «Не отправлено».

**Интерфейс.** Строки — только через типизированные ключи i18next (опечатка в ключе — ошибка TypeScript). Тема применяется скриптом в `index.html` до загрузки приложения, поэтому тёмная тема не «мигает» светлой. Пузыри сообщений и строки списка мемоизированы: новое сообщение перерисовывает только то, что изменилось.

## Ограничения

- **Токен хранится в `localStorage` в открытом виде** — это демо без бэкенда. Кроме того, GREEN-API требует токен в пути запроса, поэтому он виден во вкладке Network инструментов разработчика. В логах приложения, текстах ошибок и адресе страницы его нет.
- **Одна вкладка.** Очередь уведомлений у инстанса одна: две открытые вкладки «отбирают» уведомления друг у друга, и каждая увидит только часть входящих.
- **Только текстовые сообщения.** Фото, файлы, стикеры и прочее при получении пропускаются; отправить можно только текст.
- **Только личные чаты.** Группы, каналы и боты не показываются.
- **Список чатов не восстанавливается с сервера.** После очистки данных сайта чат создаётся заново по номеру — его переписка подгрузится.
- **Уведомления живут в очереди GREEN-API 24 часа.** Если приложение было закрыто дольше, пропущенные сообщения появятся из истории при открытии чата.
- **Статусы «доставлено» и «прочитано» не показываются:** галочка означает, что сервер принял сообщение.
- **Лимиты тарифа «Разработчик»** — см. [Подготовка GREEN-API](#подготовка-green-api).
